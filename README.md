Проект статический.

## Что в проекте особенно важно

### 1. ФСА — флагманское направление
Если задача касается UI/UX, структуры или доверия, в первую очередь проверяются страницы ФСА.

### 2. Page identity
Для service pages критично:
- уникальный `H1`;
- корректный `<title>`;
- корректный `meta description`;
- корректный `canonical`;
- корректные `OG/Twitter` метаданные;
- корректные breadcrumbs;
- корректные CTA;
- корректные скрытые поля формы и page-specific сценарии.

### 3. Контакты и форма связи
Контактный блок и форма — одни из наиболее удачных элементов сайта.  
Без отдельного запроса не нужно их радикально переделывать.

## Визуальные принципы

Сайт должен ощущаться как:
- строгий;
- экспертный;
- спокойный;
- дорогой;
- минималистичный;
- собранный;
- не шаблонный.

Недопустимо:
- визуальный шум;
- случайный редизайн;
- одинаковые карточки без конца;
- клоновые страницы;
- одинаковые CTA без различия в смысле;
- дешёвые декоративные эффекты.

## Как открыть локально

Если не требуется сборка, можно использовать простой статический сервер:

```bash
python3 -m http.server 8000

Если в проекте есть другой локальный способ запуска, сначала проверь фактическую структуру репозитория.

Как вносить изменения
Обязательно
одна задача = одна ветка = один PR;
новая задача стартует от main;
менять только реально связанные файлы;
не делать лишний рефакторинг;
не смешивать в одном PR несколько независимых задач.
Перед изменениями

Найди:

где задаётся metadata;
где задаётся H1;
где задаются breadcrumbs;
где подключается форма;
где хранятся partials;
где находятся реальные CSS и JS.
Базовая проверка перед PR

Минимум:

git diff --check
git status -sb

Для HTML-страниц также проверять:

title
meta description
canonical
og:*
twitter:*
H1
breadcrumbs
CTA
hidden fields / service_scenario
Документы проекта

Рекомендуемые документы в репозитории:

AGENTS.md — главный исполняемый канон для Codex и других агентов;
docs/ — аудиты, ТЗ, дизайн-замечания, планы внедрения;
при необходимости:
UI_SYSTEM_RULES.md
CONTENT_AND_SEO_RULES.md
WORKFLOW.md

Если этих файлов ещё нет, AGENTS.md остаётся главным источником правил работы.

Принцип работы с задачами

Если задача маленькая — делай точечно.
Если задача большая — сначала исправь критичное, потом выноси системную пересборку в отдельный PR.

Для этого проекта особенно важно не тащить в один PR:

критические SEO/identity fixes;
большой UI/UX redesign;
общую полировку стилей;
мобильную harmonization.

Это должны быть отдельные этапы.

Приоритет качества

Лучшее изменение в этом проекте:

ясное;
проверяемое;
минимально достаточное;
усиливает доверие;
не ломает хорошие рабочие блоки;
делает страницы более зрелыми и профессиональными.

## Browser QA (Playwright foundation)

Минимальная база для whole-site smoke QA уже подключена.

### Установка

```bash
npm install
npm run test:e2e:install
```

### Основные команды

```bash
# Локальный предпросмотр сайта
npm run preview

# Полный e2e прогон (desktop/tablet/mobile)
npm run test:e2e

# Smoke suite (ключевые страницы и базовые UX-проверки)
npm run test:smoke

# Отладочный запуск
npm run test:e2e:headed
npm run test:e2e:ui
```

Playwright автоматически поднимает локальный static preview server на `http://127.0.0.1:8000` через `webServer` в `playwright.config.ts`.

### Что покрывает smoke foundation

- открытие ключевых страниц (главная, каталог услуг, FSA и non-FSA services, контакты);
- базовые блоки (header/main/hero);
- проверка наличия hero CTA и не-пустого `href`;
- проверка наличия формы и ключевых полей/кнопки отправки;
- проверка навигации (desktop services menu и mobile menu toggle);
- базовая проверка `scroll-to-top` при наличии элемента.
